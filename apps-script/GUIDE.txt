اطلس ACG — راهنمای اجرا (نسخه 1.6.1)
======================================

فایل‌های این بسته
-----------------
  Code.gs           سرور: شیت، دسترسی‌ها، ورود با نام کاربری/رمز و گوگل، آپلود، ایمیل‌های خودکار
  Index.html        خود اپ اطلس (یک فایل بزرگ، حدود ۱.۵ مگابایت)
  appsscript.json   تنظیمات اسکریپت (مجوزها، تقویم و درایو)

همه‌ی مراحل را با حساب گوگلی انجام بده که شیت را ساخته (سوپر ادمین).
شیت و داده‌هایش سر جایش می‌ماند؛ فقط کد و انتشارها از نو ساخته می‌شوند.


مرحله ۰ — بایگانی انتشارهای قدیمی
----------------------------------
 Apps Script ← Deploy ← Manage deployments
 هر انتشار در لیست سمت چپ را انتخاب کن ← Archive (آیکن سطل/بایگانی) ← تأیید.
 در آخر لیست باید خالی باشد.


مرحله ۱ — جایگزینی کامل فایل‌ها
-------------------------------
 1. Code.gs را باز کن ← Ctrl+A ← Delete ← کل محتوای Code.gs جدید را بچسبان.
 2. Index.html را باز کن ← Ctrl+A ← Delete ← کل محتوای Index.html جدید را بچسبان.
    (فایل بزرگ است؛ چند ثانیه صبر کن تا چسباندن تمام شود.)
 3. appsscript.json ← Ctrl+A ← Delete ← محتوای جدید.
    (اگر دیده نمی‌شود: Project Settings ← تیک Show "appsscript.json" manifest file.)
 4. Ctrl+S. مطمئن شو کنار اسم فایل‌ها نقطه‌ی «ذخیره‌نشده» نمانده باشد.

 چک: ته Code.gs دنبال ATLAS_VERSION بگرد (Ctrl+F) — باید '1.6.1' باشد.


مرحله ۲ — اجرای setup
---------------------
 از فهرست بالای ویرایشگر setup را انتخاب کن ← ▷ Run.
 اگر اجازه خواست: Review permissions ← حسابت ← Advanced ← Go to … ← Allow.
 setup ستون username را به تب Team اضافه و پر می‌کند (مثل vahid.ameri)
 و رمز اولیه‌ی تیم را می‌گذارد: Atlas@1405  — پیغامش را می‌بینی.


مرحله ۳ — انتشار «data» (لینک اصلی تیم)
---------------------------------------
 Deploy ← New deployment ← کنار Select type روی ⚙️ ← Web app   (Library نه!)
   Description:     data
   Execute as:      Me
   Who has access:  Anyone
 Deploy ← زیر Web app، آدرس URL را Copy کن.
 چک: آدرس با https://script.google.com/macros/s/ شروع و با /exec تمام می‌شود.


مرحله ۴ — گذاشتن آدرس data در تنظیمات اسکریپت
----------------------------------------------
 ⚙️ Project Settings ← پایین صفحه Script Properties ← Edit script properties
   API_URL  =  آدرس مرحله ۳   (اگر نبود: Add script property)
 Save script properties.


مرحله ۵ — انتشار «app» (ورود با گوگل، اختیاری ولی پیشنهادی)
-----------------------------------------------------------
 Deploy ← New deployment ← ⚙️ ← Web app
   Description:     app
   Execute as:      User accessing the web app
   Who has access:  Anyone with Google account
 Deploy ← آدرس URL را کپی کن و یک جا نگه دار (مرحله ۸).


مرحله ۶ — چک با diagnose
------------------------
 از فهرست بالای ویرایشگر diagnose را انتخاب کن ← ▷ Run ← Execution log:
   نسخه‌ی Code.gs = 1.6.1
   API_URL = همان آدرس مرحله ۳
   GOOGLE_CLIENT_ID = یک مقدار …apps.googleusercontent.com
   GET  → 200 · {"ok":false,"error":"وارد نشده‌اید"}
   POST → 200 · {"ok":false,"error":"وارد نشده‌اید"}
 اگر GOOGLE_CLIENT_ID خالی بود: ته Code.gs موقتاً بنویس
   function run1() { setApiUrl('آدرس مرحله ۳') }
 run1 را اجرا کن، بعد پاکش کن و ذخیره کن.
 اگر GET صفحه‌ی Sign in داد: Who has access انتشار data روی Anyone نیست (مرحله ۳).

مرحله ۸ — تنظیمات داخل اطلس
---------------------------
 1. بک‌آفیس ← تنظیمات ← کارت Google:
      «رمز عبور تیم» ← رمز دلخواه جدید ← ذخیره   (پیشنهاد: رمز اولیه را عوض کن)
      «لینک ورود با گوگل (app)» = آدرس مرحله ۵ ← ذخیره
 2. بک‌آفیس ← افراد: ایمیل هر نفر، سمت، تیم‌ها و سطح دسترسی.
 3. بک‌آفیس ← تنظیمات: چرخه‌ی هفتگی و قوانین تسک.
 4. (اختیاری) در شیت: منوی ACG Atlas ← «نصب همه‌ی اتوماسیون‌ها».


مرحله ۹ — ارسال برای تیم
------------------------
 آدرس data + نام کاربری هر نفر + رمز تیم را بفرست. نام‌های کاربری در بک‌آفیس ← افراد
 (ستون «نام کاربری») دیده می‌شوند و از همان‌جا قابل تغییرند:
   vahid.ameri · jalil.alizadeh · vahid.keyvanian · mehrzad.goli · athena.dehghan
   ali.sormeili · ali.salemeh · mehrsa.dabir · babak.maroufi · amin.zafari · hanie.mansurkiae
 هر کس ۹۰ روز روی همان دستگاه وارد می‌ماند. کسی که تقویم و Meet می‌خواهد، «ورود با حساب گوگل» را می‌زند.
 ۸ بار رمز اشتباه = ۱۰ دقیقه قفل برای آن نام کاربری.


قانون‌های امنیتی
-----------------
 - شیت را با هیچ‌کس به اشتراک نگذار. بقیه فقط از لینک وارد می‌شوند و سرور فقط داده‌ی مجاز
   هر نفر را می‌فرستد.
 - رمز تیم مشترک است؛ اگر کسی از تیم رفت، رمز را عوض کن و ورود او را در بک‌آفیس غیرفعال کن.


به‌روزرسانی‌های بعدی (بدون عوض شدن لینک‌ها)
---------------------------------------------
 فایل‌های جدید را مثل مرحله ۱ جایگزین کن ← Deploy ← Manage deployments ←
 هر انتشار ← ✏️ ← Version: New version ← Deploy   (برای data و app هر دو).
 هیچ‌وقت برای به‌روزرسانی New deployment نزن؛ لینک‌ها عوض می‌شوند.
 بعد از هر به‌روزرسانی: پایین صفحه‌ی ورود و خروجی diagnose باید نسخه‌ی جدید را نشان دهند.
