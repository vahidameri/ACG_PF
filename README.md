# ACG Portfolio — سیستم مدیریت و مانیتورینگ پورتفولیو پروژه‌ها

داشبورد وب برای **مدیر برنامه** (دستیار روزانه: تسک‌ها، فالوآپ‌ها و پیشنهادهای هوشمند) و **لیدرشیپ** (مانیتورینگ دقیق سلامت، رودمپ، ریسک و بودجه). داده‌ها در **Google Sheets** نگهداری می‌شوند و به سرور اختصاصی نیازی نیست.

```
Google Sheet (دیتابیس)  ⇄  Apps Script Web App (API رایگان)  ⇄  وب‌اپ React (هاست استاتیک رایگان)
```

### موتور سلامت خودکار

سلامت هر پروژه (سبز، زرد یا قرمز) **محاسبه می‌شود و دستی وارد نمی‌شود**. دلیل هر رنگ هم نمایش داده می‌شود:

- فاصله‌ی پیشرفت با زمان سپری‌شده (۱۰٪ عقب: زرد، ۲۰٪ عقب: قرمز)
- ددلاین گذشته، یا کمتر از دو هفته تا ددلاین با پیشرفت کمتر از ۸۵٪
- مایلستون‌های عقب‌افتاده
- ریسک‌های باز با امتیاز ۱۵ یا بیشتر (احتمال × اثر)
- مصرف بودجه‌ی بیشتر از ۱۰۰٪ یا جلوتر از پیشرفت
- تسک‌های مسدود و معوق، و عقب‌ماندگی اسپرینت جاری

اگر لازم شد، ستون `health_override` در شیت اجازه می‌دهد سلامت را دستی تعیین کنید. در این حالت برچسب «سلامت دستی» کنار پروژه نمایش داده می‌شود.

## راه‌اندازی

### ۱. Google Sheet و API (حدود ۵ دقیقه)

1. یک Google Sheet خالی بسازید.
2. از منوی **Extensions → Apps Script**، محتوای [`apps-script/Code.gs`](apps-script/Code.gs) را جایگزین کنید و ذخیره کنید.
3. تابع `setup` را اجرا کنید (Run) و دسترسی‌ها را تأیید کنید. همه‌ی تب‌ها ساخته می‌شوند و **کلید ادمین** در تب `Users` قرار می‌گیرد.
   - اختیاری: تابع `seedDemo` را اجرا کنید تا شیت با داده‌ی نمونه پر شود.
4. **Deploy → New deployment → Web app**
   - Execute as: **Me**
   - Who has access: **Anyone** (امنیت با کلید شخصی هر کاربر تأمین می‌شود)
5. آدرس `.../exec` را کپی کنید.
6. اختیاری: تابع `installDailyDigest` را اجرا کنید تا هر روز حدود ساعت ۷:۳۰ صبح ایمیل خلاصه ارسال شود. برای ارسال به ایمیل دیگر، در Project Settings یک Script Property با نام `DIGEST_TO` بسازید.

پس از اجرای `setup` (یا یک بار باز کردن دوباره‌ی شیت)، منوی **ACG Portfolio** داخل شیت اضافه می‌شود. از این منو می‌توانید کاربر جدید بسازید و کلیدش را بگیرید.

### ۲. نقش‌ها و دسترسی

هر ردیف تب `Users` یک کاربر است:

| key | name | email | role | active |
|---|---|---|---|---|
| کلید تصادفی | دکتر … | ceo@… | `viewer` | TRUE |

- `admin` و `editor`: مشاهده و ویرایش
- `viewer`: فقط مشاهده (مناسب برای مدیرعامل و لیدرشیپ)

تمام تغییرات در تب `AuditLog` ثبت می‌شود (چه کسی، چه زمانی، چه چیزی).

### ۳. اجرای وب‌اپ

```bash
npm install
npm run dev        # توسعه روی http://localhost:5173
npm run build      # خروجی استاتیک در dist/
```

اولین بار داشبورد در **حالت نمایشی** با داده‌ی نمونه باز می‌شود. در صفحه‌ی **تنظیمات**، آدرس Web App و کلید را وارد کنید، «تست اتصال» را بزنید و ذخیره کنید.

### ۴. انتشار (رایگان)

- **GitHub Pages:** ورک‌فلو [`.github/workflows/deploy.yml`](.github/workflows/deploy.yml) آماده است. در Settings → Pages، گزینه‌ی Source را روی «GitHub Actions» بگذارید. با هر پوش روی `main` نسخه‌ی جدید منتشر می‌شود.
- **Vercel / Netlify:** ریپو را import کنید. دستور بیلد `npm run build` و پوشه‌ی خروجی `dist` است.
- اختیاری: با تنظیم متغیر `VITE_API_URL` هنگام بیلد، آدرس API از قبل پر می‌شود و کاربران فقط کلید خود را وارد می‌کنند.

## ساختار شیت (هر تب = یک جدول)

| تب | ستون‌ها |
|---|---|
| `Projects` | id, code, name, description, category, owner, sponsor, status, priority, phase, start_date, end_date, budget, spent, progress, health_override, objective |
| `Scope` | id, project_id, item, type (in/out), status, change_note, date |
| `Milestones` | id, project_id, title, planned_date, actual_date, status, owner, weight |
| `Sprints` | id, project_id, name, start_date, end_date, goal, committed_points, completed_points, status |
| `Tasks` | id, project_id, sprint_id, title, description, assignee, reporter, status, priority, due_date, points, tags, created_at, completed_at |
| `FollowUps` | id, project_id, subject, person, channel, due_date, status, priority, notes, created_at, done_at |
| `Risks` | id, project_id, title, type (risk/issue/dependency/decision), probability (۱–۵), impact (۱–۵), owner, mitigation, status, due_date |
| `Team` | id, name, role, email, team |
| `Allocations` | id, member_id, project_id, percent |
| `Updates` | id, project_id, week_date, author, health, summary, done, next, blockers |

**مقادیر مجاز:**

- `status` پروژه: `planning` · `active` · `on_hold` · `completed` · `cancelled`
- `priority`: `critical` · `high` · `medium` · `low`
- `status` تسک: `todo` · `in_progress` · `review` · `blocked` · `done`
- `status` فالوآپ: `open` · `waiting` · `done`
- `status` مایلستون: `pending` · `in_progress` · `done` · `missed`

**نکات:**

- تاریخ‌ها در شیت به‌صورت میلادی و با قالب `YYYY-MM-DD` ذخیره می‌شوند، ولی در داشبورد همه‌جا شمسی نمایش داده و انتخاب می‌شوند.
- اگر `progress` خالی باشد، پیشرفت از وزن مایلستون‌های انجام‌شده محاسبه می‌شود.
- برای Burndown، تاریخ `completed_at` تسک‌ها هنگام «انجام شد» خودکار ثبت می‌شود.
- می‌توانید مستقیم در شیت هم ویرایش کنید. داشبورد هر ۲ دقیقه خودکار همگام‌سازی می‌شود و دکمه‌ی همگام‌سازی دستی هم دارد.

## ساختار کد

```
apps-script/Code.gs      بک‌اند: API، نقش‌ها، لاگ، ایمیل روزانه، داده‌ی نمونه
src/lib/                 مدل داده، تقویم شمسی، موتور سلامت و متریک‌ها، لایه‌ی همگام‌سازی
src/components/          کامپوننت‌های UI، فرم‌های ویرایش، تقویم، کانبان، نمودارها
src/pages/               صفحه‌ها
src/data/demo.ts         داده‌ی نمونه برای حالت نمایشی
```

تکنولوژی‌ها: React 19، TypeScript، Vite، Tailwind CSS، Recharts، lucide-react و فونت وزیرمتن (همراه برنامه بسته‌بندی شده، بدون وابستگی به Google Fonts).
